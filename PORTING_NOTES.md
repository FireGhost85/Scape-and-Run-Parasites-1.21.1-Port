## Crash fixes: death explosion and Yelloweye (2026-10-08)
- [CHG] Root cause 1 (crash after the death explosion of Tozoon and others, and the world that could not be rejoined): 18 entity types had no renderer registered (the generator of `ClientRenderers` did not parse the method reference and `SRPProjectile` registrations of the 1.12 handler). 1.12 drew nothing for such an entity, 1.21 throws a NullPointerException in `EntityRenderDispatcher.shouldRender`. A parasite dying spawns one of them (remains, projectiles); the entity is saved in the world, so every rejoin crashed on the first frame. Fix: `SRPProjectile` (billboard quad renderer) ported, `RenderRemain` / `RenderWaveShock` registered, and every entity type of the mod that still has no renderer gets `RenderNothing` (so this cannot happen again). The world itself is not damaged: rejoining works with the fixed build.
- [FLAG] AboHead, Quac (carrier_worm) have a ported renderer class that the original never registered (invisible in 1.12); they are now registered. Seeker has neither a model nor a renderer in the jar and renders nothing.
- [CHG] Root cause 2 (client crash in `tickDeath` of Lice/Gnat, same family): `PacketDistributor.send*` from entity code that also runs on the client (death animation) throws "Cannot send clientbound payloads on the client" (and would send from the render thread in single player). All 87 sends now go through `network/SRPSend`, which only sends from the server thread.
