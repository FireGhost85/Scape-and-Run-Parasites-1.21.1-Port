# PORTING_NOTES / CHANGELOG

Every deviation from SRP 1.10.9 (1.12.2) is listed here. `[ADD]` = addition beyond the original, `[CHG]` = necessary change, `[FLAG]` = needs your decision.

## Log
- [CHG] Project scaffolding: template example block/item/tab removed from `ScapeAndRunParasites`; template `Config.java` repurposed to register the four SRP config specs.
- [FLAG] Beckon Stage V is unregistered in the jar (see docs/PORTING_PLAN.md Q1).
- [FLAG] Config default `0` for ints with min 1 and no initializer (`ancient/preeminent/derived OneMindDeathV`) is clamped to 1 (Forge `getInt` behaviour); kept as 1.
- [CHG] Beckon Stage V (Q1, decided): ported dormant (class/model/lang only; not registered, not spawned), as in the jar.
- [CHG] Dimension 270 (Q2, decided): kept as an unmapped legacy id in the phase config; has no effect.
- [CHG] Dimension-id config lists (7 entries) are string lists: legacy numbers (0=overworld, -1=nether, 1=end) or resource locations (e.g. `minecraft:overworld`). Defaults unchanged.
- [FLAG] Difficulty cap in the jar uses integer division (Peaceful/Easy -> cap 0, Normal/Hard -> 10), not the 0.5/1/1.5 multipliers of the brief. Jar wins; ported as in the jar.
- [FLAG] World-creation "pace" choice (`choiceNUMBER` 0..3 -> x0.5 / x1 / x3 / x10; cooldown ignored and cap bypassed for 3) exists in the jar but not in the brief. Ported.
- [FLAG] `initdislo020Config` is never called in the jar: its 6 entries only keep defaults. Kept as defaults.
- [FLAG] Original NBT bug: locked parasites write `dimensionId` but read `dimId`. Port uses one consistent key; no legacy data to migrate.
- [ADD scope] Extra jar-only systems (celestial events, Star biomes/blizzards, meteors, Harlequin, Field Guide, 22 commands) are ported after core.
- [CHG] M2 save data: one `SRPSaveData` for the whole server (overworld storage, `data/srparasites_global_data.dat`) with one entry per dimension, keyed by resource location. The original used Forge per-world storage (one instance per dimension, holding stale copies of the other dimensions' config start entries), which made the cross-dimension parts (overworld daily update, Ubiquitous Development level, `/srpudevelopment` listing) inconsistent. Per-dimension gameplay is unchanged. **[FLAG]** tell me if you want the per-dimension-instance behaviour back.
- [CHG] Dimension ids: config/commands accept legacy numbers (0, -1, 1) or resource locations; other legacy numbers (e.g. 270) are kept as unmapped keys. Debug CSV keeps `evolution_points_dim0/-1/1.csv` names.
- [CHG] The world's pace choice is copied into the save data once, when it is created. The original also re-copied the static GUI value whenever a new dimension entry was added, which could silently change the pace of an existing world.
- [CHG] SavedData NBT is flattened (one compound per dimension) and the locked-parasite key mismatch (`dimensionId` written / `dimId` read) is fixed. No 1.12.2 data can be loaded, so no migration is needed.
- [CHG] Dislodgment 2 end effect (`disloNumber2`) ran once per loaded entity in the original, which could summon repeatedly. It runs once in the port.
- [CHG] Sounds: `QUAC_HURT` was assigned twice and `QUAC_DIG` stayed null in the original (EntityQuac plays it). Port registers `quac.hurt` and `quac.dig` separately. `FLOG_*`, `HEBLU_STEP`, `BODIES_SHOOT`, `ANCIENT_ADVANCEMENT` are declared but never assigned or used in the jar and are not registered.
- [CHG] Parasite per-entity dislodgment flags (`disloNumberX` fields) become `IDislodgmentTarget.setDislodgment(position, value)`, implemented by `EntityParasiteBase` in M4.
- [CHG] `SRPPacketRequestEvoPhaseClient`, music state machine (`soundTwo/soundThree/getMusicPhase`) and the world-settings screen are ported with the client milestone; M2 only has the state, the three server->client payloads and `playMovingSound`.

## Blocks (M3 part, 2026-10-08)
Details and file list in `porting/notes/blocks.md`.
- [CHG] Metadata blocks became a `variant` blockstate property with one item per variant, `<block>_<variant>` (the old `tile.srparasites.<block>_<variant>.name` keys). Blocks: parasiterubble, parasitestain, parasitetrunk, parasiteplank, parasiterubbledense, parasiteloot, parasitebush, infestedbush, infestedore, parasitesapling, parasitecanister, srpweb, evolutionlure, the six gore blocks, the two parasite slabs. There is no item named after the block itself.
- [CHG] Slabs: half and double block are one block with the vanilla slab type (also waterloggable now). The names `*_slab_double`, `parasiterubbleslabdouble`, `parasitestainslabdouble` no longer exist. The original double parasite slabs dropped two double-slab items when broken (`BlockSlab.quantityDropped` with the double block as the item): duplication of material, fixed by the vanilla behaviour (two half slabs).
- [CHG] `id:meta` strings: `porting/spec/meta_map.json` (58 vanilla blocks, 502 metas, 142 renames, all checked against 1.21.1 registries) and `util/BlockIds`. Strings in the 1.21 form (`minecraft:oak_log[axis=x]`) are accepted too. The 8 `minecraft:log2` entries with meta 2, 3, 6, 7, 10, 11, 14, 15 in the config defaults are not valid 1.12 states either and resolve to nothing.
- [CHG] Dead blood: `FluidType` density 3000, viscosity 1500, temperature 310, light 0; the Forge `BlockFluidClassic` tick rate (viscosity / 200 = 7) and no source creation are kept; swim, drown and extinguish like water (the original answered "inside water" for any material query). No bucket (the universal bucket was never enabled). `ModCompatibility.FLUIDLOGGED_API` is never set in the jar, so the head check always applies.
- [CHG] Fog nullifier: the smoke particles used the client-only `World.spawnParticle` on the server and never showed; not ported. The permission check `canCommandSenderUseCommand(2, "srpbarrier")` of the parasite barrier is `hasPermissions(2)`. The barrier tooltip class (`ItemBlockParasiteBarrier`) was never used by the original and is not ported.
- [CHG] Parasite fog uses `Properties.air()` (the original `Material.AIR` made `isAirBlock` true). Risk: a chunk section that holds only air and fog is not rendered by 1.21. Revisit if fog is invisible high above the ground.
- [CHG] Snow grass keeps the 1.12 box as collision box (the class only overrode `getBoundingBox`); the tall one is a 2 block high solid box. Gothshroom, residue plants and alveoli growth also collide with their box.
- [CHG] Thornshade: the snowfall clause `isRainingAt && temperature < 0.15` is effectively unreachable in 1.21 (`isRainingAt` excludes cold biomes); snow only comes from adjacent snow. It has no item and drops nothing, as in the original (the berry plants it).
- [CHG] Infested furnace is a vanilla `AbstractFurnaceBlockEntity` (cook time from the smelting recipe, 200 for all vanilla smelting recipes, instead of a fixed 200; same slots, faces, stack limit, experience on take). Infuser furnace: recipes stay code-registered (`InfuserFurnaceRecipes`, 9 recipes), the menu keeps the 1.12 slot order and the shift-click quirk (it can never fill the infuse input because it merges into the output slot index 3), it only ticks on the server.
- [CHG] Parasite canister (active): 40 slots, stack limit 100, the screen shows 36 slots (`ContainerChest` size / 9 rows in 1.12); the open counter only counts creative players (`isCreative`, original quirk kept).
- [CHG] Purifier: the mapping file is `config/srparasites_purify_mappings.txt` (created with 1.21 ids on first use; 1.12 ids are accepted); the dev-folder and classpath lookups of the original are dropped. The start pulse uses `ServerLevel.sendParticles` (blue dust, portal), as the 1.12 `WorldServer.spawnParticle` did.
- [CHG] Relay: block, node and controller entity ported (formed flag, 38 nodes, dismantle, relink, module slot, cooldown, NBT). The scanner (reports, `ScanRegistry`, scanner menu and screen, `performScan`) comes with the Relay in M6; until then using the controller or a node does nothing (documented in the two block classes).
- [CHG] Damage types for the four `new DamageSource(name)`: `sepeku`, `biomass`, `srp_dod_block`, `parasite_mouth` (data + `minecraft:bypasses_*` tags); hunger exhaustion 0.3 like `DamageSource`'s default.
- [CHG] Fixed while checking: `BlockAssimilatedReed` bases (coarse dirt, podzol, red sand were `dirt:1/2`, `sand:1`), `BlockBiomassBlock` particle, `BlockTressesHair`/`BlockWebBase` codec access, `BlockParasiteSapling` growth event call.
- [CHG] Not ported: `BlockColonyOutpost` and `BlockGlassBase` (dead classes in the jar).
- [FLAG] SRG sound fields without a name in `srg_names.csv`: `field_187577_bU` (gothshroom grouping, ported as `GRASS_PLACE`), `field_187715_dR` and `field_187635_cQ` (fog nullifier clear and break, ported as `FIRE_EXTINGUISH` and `ITEM_BREAK`).
